# Changelog

Все изменения ниже сделаны в одном рабочем цикле и ещё не закоммичены.

## Главное меню

### Полностью переделано по референсу (дизайн «velocity»)
- Фон — пользовательские обои с лёгким параллаксом от мыши, поверх мягкая тёмная подложка с плавным «дыханием»
- Крупный логотип `shizavisuals.` по центру, жирный шрифт, с обводкой для читаемости на светлых обоях
- Ряд 1: две пилюли `Одиночная игра` (светлая заливка + тёмный текст) и `Сетевая игра`
- Ряд 2: три пилюли — `Настройки`, `Обои`, `Выход`
- Поведение как в референсе: радиус 5, градиентная заливка `40,40,48 → 24,24,31`, рамка `0.5px` с alpha `45 + 75 × hover`, текст `160,160,172 → 240,240,245` при `hover > 0.5`, плавная интерполяция `0.12` за кадр с поправкой на дельту (не зависит от FPS)
- Хоткеи: `S` / `M` / `O` / `W` / `Q`

### Выбор обоев
- Кнопка `Обои` в нижнем ряду открывает панель с превью, выбор кликом, стрелками или Enter, закрытие по клику мимо или Esc
- Автоскан папки каждые 2 секунды, хранение выбора в `config/shizavisuals/menu.json`

### Исправления обоев
- **Формат определяется по содержимому, а не по расширению.** Раньше файл с сигнатурой не-PNG молча выпадал из списка (та же проблема, что была с `macos_wallpaper.png`)
- Поддержка **PNG, JPEG, BMP, GIF, WebP** независимо от расширения
- Подключён WebP-декодер `org.sejda.imageio:webp-imageio` (1 МБ, вложен в jar) — Minecraft сам WebP не читает
- Размеры читаются из заголовков: PNG, JPEG (поиск SOF-маркера), GIF, BMP, WebP (VP8/VP8L/VP8X)
- Нечитаемый файл больше не игнорируется молча, а пишет понятное предупреждение в лог
- Имена-хеши вида `05744fbe…` заменяются на нормальные `Wallpaper 1`, `Wallpaper 2`
- `macos_wallpaper.png` перекодирован из JPEG в настоящий PNG (была битая сигнатура, из-за чего фон не грузился)

## Косметика Pulse

- Новая фича `CosmeticsFeature`: 4 категории, 39 косметик, 135 ресурсных файлов
  - `wings` — 10, `hat` — 14, `bodywear` — 9, `pet` — 6
- Полный парсер Bedrock-моделей: геометрия, UV, анимации по каналам, посадка на игрока
- Переключатель **`Translucent`** (по умолчанию выключен) — стабильный Cutout вместо проблемного blending, outline у translucent-варианта отключён
- Настройки: крылья / шляпа / рюкзак / питомец + `Self Only`

### Исправлены битые текстуры (20 из 39)
Текстуры были целые, но UV считались по размеру, заявленному в `geometry.json`, а он часто в 2–4 раза меньше реального PNG — модель сэмплировала левый верхний угол:
- `wings 61` — заявлено 258×387, PNG 516×774
- `wings 62` — заявлено 32×32, PNG 64×64
- **все рюкзаки** `bodywear 36–44` — заявлено 64×64, PNG 256×256 (4x)
- также `wings 63, 64, 65, 99`, `hat 98`, `pet 45, 46, 84, 135`

Теперь UV нормализуются по фактическому размеру картинки (читается заголовок PNG), с откатом на объявленный размер, если файл не читается. Позиции глифов тоже стали точнее — раньше они «плыли» на кернинге и трекинге.

Тест `textureUvsAreNormalizedAgainstTheRealImage` (параметризованный, 39 кейсов) валит билд, если появится новый такой рассинхрон.

## Оптимизация

### Горячие пути
- **`MineStatus`** — сканировал все сущности уровня дважды за кадр (`canShow` + `draw`) с `ArrayList` + `stream()` + `Comparator` и тремя `toLowerCase()` на стенд. Теперь троттлинг 500 мс + кэш, один проход до якоря и один до соседних, имя в нижний регистр один раз
- **Караоке** — на каждый символ каждый кадр делались `substring` + `measureWidth`, обрезка по ширине была O(n²). Раскладка строки теперь кэшируется по (текст, шрифт, размер), позиции берутся из `penX`, ширина глифа — из `advanceEm`, обрезка — бинарный поиск. Ноль аллокаций в кадре
- **`MsdfFont.shapeCache`** — был `LinkedHashMap` с access-order: не потокобезопасен и на гонке способен зависнуть. Заменён на `ConcurrentHashMap` с отсечкой по объёму; `...` для `ellipsize` кэшируется полем

### Мелкие
- `EspSpriteRenderer` — `new float[2]` на каждую вершину (6 на спрайт) плюс 4 лишних повторных поворота; теперь 4 угла считаются один раз, порядок вершин и UV сохранён 1:1
- `TargetScanRenderer` — `new ScanMotion` на каждую сущность в кадр убран
- `String.format` убран из per-frame путей: время трека, кулдауны, зелья
- `CooldownsElement` — массив `Item[]` создавался каждый кадр, стал `static final`

- Удалены `RainFeature`, `RainFall`, `WetSurfaceRenderer` и пакет `utils/render/rain/`
- Удалены шейдеры `core/winter_textured.*`, `core/winter_color.*`, `post/wet_surface.fsh`

## Стабильность

- **Крах при запуске `NoClassDefFoundError: com/github/weisj/jsvg/parser/SVGLoader` исправлен.** `processResources` перезаписывал массив `jars` в `fabric.mod.json` целиком и затирал записи, которые Loom добавляет для `include`-зависимостей — в собранном jar физически лежал `META-INF/jars/jsvg-2.1.0.jar`, но в списке `jars` его не было, поэтому Fabric его не подхватывал. Теперь списки объединяются и сортируются детерминированно
- Библиотеки в списке `jars` теперь всегда полные: 14 bundled-модов + `jna`, `jna-platform`, `jsvg`, `webp-imageio`
- `GuiTexture` больше не роняет игру, если SVG-библиотека недоступна: при отсутствии `jsvg` иконки рисуются заглушками, в лог пишется одно понятное сообщение вместо `Unreported exception`
- **Multibot удалён полностью** (пакет `bot/`, 16 файлов, ~2700 строк, `shizavisuals.bot.mixins.json`, client-entrypoint, хуки в `ConnectionMixin`) — по запросу
- Попутно выяснилась причина его поломки: в 26.2 сервер пишет байт-флаг перед каждым пакетом после `login_compression`, а отложенные пакеты не успевали обработаться — бот всегда падал в реконнект по кругу
- `ShizaVisuals.onInitialize` больше не грузит клиентские классы на выделенном сервере — мод теперь запускается на сервере
- Добавлен `jsvg 2.1.0` во вложенные jar — чинит падение `NoClassDefFoundError: com/github/weisj/jsvg/parser/SVGLoader` в рантайме
- Защитные проверки: контекст соединения и guard'ы поколений в обработчиках пакетов, `Feature.enabled` стал `volatile`, жизненный цикл `WaveEffect`, фильтрация status-событий, fallback при shutdown
